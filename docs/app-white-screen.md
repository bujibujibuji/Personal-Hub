# 为什么 App 会白屏？（一次真实排错记录）

一句话版本：**App 的代码是整包交给手机自带浏览器内核执行的，代码里只要有一个它看不懂的写法，整个文件就一句都不执行，页面自然白屏；闪屏等 10 秒才消失，是因为官方启动图有 10 秒兜底。**

这篇文档不用专业术语，记录这次白屏从发现到修好的完整过程，方便以后遇到类似问题时快速判断。

---

## 1. 白屏时长什么样

- 点开 App，先看到启动图（Personal Hub 图标）；
- 启动图停大约 10 秒后消失；
- 页面区域一片白色，但底部“首页 / 笔记 / 日记”导航栏还在；
- 网页版（H5）打开却完全正常。

这个组合非常有辨识度：**底部导航栏还在，说明 App 本身启动了；页面空白，说明页面代码没有跑起来。**

## 2. 用大白话解释原因

### 2.1 App 页面其实就是网页

uni-app 打出来的 Android App，界面部分仍然是由手机系统里的“浏览器内核”（WebView）来渲染的。
所有页面的逻辑代码会被打包成一个大文件：`app-service.js`。

### 2.2 浏览器读代码是“整篇一起读”

浏览器执行这个文件之前，要先把它完整读一遍。
只要遇到一个它的版本不认识的写法，它不是“跳过这一句”，而是**整篇都拒绝执行**。

就像给一个只懂简体中文的人一篇夹杂生僻繁体字的文章，他不是看不懂那一个字，而是干脆整篇不读。

结果就是：

- 页面代码一行都没执行；
- 页面没有任何内容 → 白屏；
- 底部导航栏是手机原生画的，不依赖这段代码 → 它还正常显示。

### 2.3 为什么偏偏停 10 秒

uni-app 的启动图有个保护机制：正常情况下，页面画好之后会主动通知“可以关掉启动图了”；
如果一直没收到通知（因为代码根本没跑），最多等 10 秒就强制关闭。

所以“10 秒”不是加载慢，而是**页面一直没画好，启动图在等一个永远不会来的通知**。
页面一旦正常渲染，这 10 秒会自然消失。

### 2.4 根本原因：代码用到了“新语法”

这次打包出来的代码里有两类东西，老一些的手机浏览器内核看不懂：

1. **JavaScript 新语法**
   比如 `async/await`、对象展开 `{ ...obj }`。这些在较新的 Chrome 里没问题，但在旧内核里是语法错误。

2. **Markdown 库里的“新正则表达式”**
   项目原来用的 `marked` 18 版本，内部用了命名分组、`\p{L}` 之类的写法，需要 Chrome 64 以上才能解析。
   更麻烦的是：**代码降级工具只会改写普通语法，不会改写正则表达式**，所以它悄悄留了下来。

手机只要有一个环节不达标，`app-service.js` 就整包罢工，最终就是白屏。

## 3. 为什么第一次修复没有成功

第一次的修复把构建目标降到了 `es2018`，并补了一些缺失的方法。
方向是对的，但漏了两点：

- `es2018` 仍然允许 `async/await` 和对象展开，旧内核还是读不懂；
- `marked` 18 的正则没有处理，它依然要求 Chrome 64+。

等于文章里最难的几个字还在，读者还是整篇不读。

## 4. 这次是怎么修的

按“从根上保证旧内核能读懂”来做，而不是只补一两个方法：

| 做法 | 作用 |
| --- | --- |
| 构建目标降到 `es2015` | 把 async/await、对象展开等全部改写成老写法 |
| 把 `marked` 18 换成 `markdown-it` 13 | 新库不含旧内核不认识的正则语法，Markdown 效果不变 |
| 在产物最前面插入一小段 ES5 兼容代码 | 保证连构建工具自己生成的辅助代码也不会因为缺方法而报错 |
| 补齐旧内核缺少的内置方法 | 如 `padStart`、`Object.entries`、`Promise.finally`、`matchAll` 等 |
| 增加 `npm run check:app-syntax` | 每次构建后自动检查，防止以后升级依赖又把这些新语法带回来 |
| 启动出错时弹出“启动异常” | 万一还有问题，手机上能直接看到原因，而不是只能看到白屏 |

## 5. 怎么确认真的修好了

不是“重新打一次包试试”，而是直接检查打包产物：

1. 用语法检查工具按 ES2015 解析 `app-service.js`，通过；
2. 扫描整个文件，确认没有命名捕获组、`\p{...}`、后行断言等新正则；
3. 从最终 APK 里把 `app-service.js` 解出来，再检查一遍；
4. 确认 H5 页面照常渲染。

这几步都通过后，才重新云打包安装。

## 6. 以后再遇到白屏，按这个顺序看

1. **底部导航还在、内容空白**：先怀疑代码整包没执行（语法/兼容性问题），不是网络问题。
2. **闪屏固定约 10 秒**：说明首页一直没渲染完成，是“结果”不是“原因”。
3. 让手机连电脑，用 HBuilderX 自带的 adb 看日志：

   ```powershell
   & "C:\Download\HBuilderX.5.34.2026102909\HBuilderX\plugins\launcher-tools\tools\adbs\adb.exe" logcat -v time |
     Select-String -Pattern "Uncaught|chromium|app-service|console"
   ```

4. 更直接：HBuilderX 里“运行到 Android App 基座”，控制台会显示完整报错。
5. 每次改完依赖，执行：

   ```powershell
   npm run build:app
   npm run check:app-syntax
   ```

## 7. 一句话记住

**白屏不是“页面加载慢”，而是“页面代码整包没跑起来”；老手机浏览器内核读不懂新语法时，一行都不会执行。**
